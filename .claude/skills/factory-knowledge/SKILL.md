# Factory knowledge
1. Read docs/knowledge/CAPABILITY_MAP.md — reuse before building.
2. Read docs/knowledge/REPO_MAP.md — which repo already solved it (automation, installer, sync, motion, MCP).
3. Read docs/knowledge/LESSONS.md — don't repeat a known mistake.
4. Library choice: docs/knowledge/GITHUB_RADAR.md (permissive licences only inside products).
5. After a fix: add the lesson (what happened → fix → rule) and update the capability status in the same commit. Never mark "verified" without a test run, nor "field_accepted" without a real customer.
