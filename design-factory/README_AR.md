# 🎨 مصنع التصميم

المشكلة اللي بنحلها: كل مرة وكيل برمجي بيعمل واجهة شكلها مختلف، ومسافات وألوان مختلفة، وأحيانًا كروت كتير مالهاش معنى، أو مشاكل في العربي والموبايل.

**الحل:** عندك الآن نظام ألوان ومسافات ومكونات، وواجهة تجريبية شغالة دون إنترنت، ومصادر تصميم عالمية مربوطة بإصدارات محددة، ودستور لوكيل البرمجة، واختبارات للشكل والتفاعل.

## ✨ التوسع الإبداعي: حركة وطبقات وفيديو
- [افتح معمل الحركة والطبقات](creative-lab/index.html) على جهازك بدون نت. تحكم في العمق والوقت، شغّل/أوقف المشهد، وشوف العربي والإنجليزي.
- [تعليمات الوكيل الإبداعي](CREATIVE_AGENT_PLAYBOOK.md) و[معمارية المؤثرات](CREATIVE_ARCHITECTURE.md) و[وصفات جاهزة](creative-recipes/).
- ١٧ مصدر إضافي مربوطين بإصدارات ثابتة، منهم استوديو الأنيميشن والعروض والفيديو الموجودين في مشاريعك. مش هنحط محرك 3D أو محرر فيديو داخل كل برنامج.
- عشان تضيف تأثيرات خفيفة لمشروعك: `python design-factory/scripts/install.py --target "C:\\My-App" --creative` لمعاينة التغييرات، وأضف `--apply` للنسخ بدون استبدال ملف موجود.

## استخدمه في 3 خطوات

1. افتح [الواجهة التجريبية](reference/index.html) بعد تنزيل المشروع من جيتهاب، وجرّب تغيير اللغة والمظهر والبحث وإضافة شخص.
2. لو بتبدأ مشروع جديد، خلي الوكيل يقرأ [تعليمات التصميم](AGENTS.md) و[دستور التصميم](DESIGN_CONSTITUTION.md) و[طريقة العمل](WORKFLOW.md).
3. لو عندك مشروع موجود، جرّب أداة التركيب الآمنة، من غير ما تلمس الملفات الموجودة:

```powershell
python design-factory/scripts/install.py --target "C:\\My-App"
# معاينة فقط، لا تعدّل أي شيء
python design-factory/scripts/install.py --target "C:\\My-App" --apply
# تكتب الملفات الناقصة فقط، من غير استبدال
```

راجع مكان مجلد الملفات العامة في برنامجك؛ اختلاف نظام Python/React قد يحتاج تعديل طريقة استيراد ملفات التصميم.

## المصادر الستة

[UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) • [Tabler](https://github.com/tabler/tabler) • [Anthropic](https://github.com/anthropics/skills) • [Vercel](https://github.com/vercel-labs/agent-skills) • [shadcn/ui](https://github.com/shadcn-ui/ui) • [Web Awesome](https://github.com/shoelace-style/webawesome).

الستة مربوطين بالمصنع بطريقة Git Submodules، **مش Forks على حسابك**. ده ربط مباشر بمصدر كل مشروع وإصدار محدد. عشان تجيب ملفاتهم فعلًا محتاج تزامن من جيتهاب مرة واحدة؛ بعد كده نسخة العميل تشتغل أوفلاين بالملفات المتضمنة في حزمة المنتج فقط.

## أنواع المشاريع

- ويندوز بواجهة ويب/بايثون: ابدأ بمكونات المصنع الخفيفة. ممكن تستخدم Tabler بدلها لو المشروع محتاج واجهات إدارة Bootstrap كاملة.
- تطبيق مكونات ويب: ممكن تختار Web Awesome *بدل* Tabler.
- مشاريع React: ممكن تستخدم shadcn/ui.
- 3D والمونتاج: نشارك الألوان والعمليات العامة فقط، ما نفرضش عليهم شكل لوحة إدارة.

## مهم جدًا

الاختبارات الآلية بتثبت إن ملف الواجهة بيتفتح وأزراره بتتحرك بالشكل المتوقع على أحجام مختلفة، لكنها مش بديل عن مراجعة لقطة الشاشة بعين بشرية. قبل إطلاق أي منتج لازم [فحص التصميم](QA_CHECKLIST.md) يتعمل على تطبيق العميل الحقيقي.

**ده الأساس الهندسي، مش شهادة إن كل برنامج عندك بقى جميل تلقائيًا.**
