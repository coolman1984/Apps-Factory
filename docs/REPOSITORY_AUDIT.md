## Cross-repository diagnosis (observations, not numerical incidence claims)
1. **Some repos are fully operational, others planning documents or demos.** Require explicit `planned / implemented / verified / field_accepted` lifecycle status per capability.
2. **Desktop, LAN, browser and cloud mixes** create different security and licensing needs. A universal copy-and-paste server will fail; a common contract with profile-specific adapters will scale.
3. **Repeated identity, roles, sample data, backup, installers, error/help and subscription topics.** Centralize capabilities after cross-product tests; do NOT centralize every domain rule.
4. **Documentation-based PASS claims often have clear external test limitations.** CI green is not customer acceptance.
5. **Worktree and branch-management problems are recorded** (e.g. Work-Tasks). Require expected repository/branch verification before any write.
6. **Offline data and Excel are recurring strengths.** Keep first-class import/reconciliation/backup workflows even in products where cloud is optional.
7. **Vendor support/monetization is inconsistent by product.** Central entitlement, support consent and commercial contract standards address the business risk.

## Evidence levels
- **Inspected**: directly read current default-branch README or indicated source/document (30/30 root or alternative inspection; one folder-only source).
- **Repository feature verified**: NOT claimed by this audit.
- **Full runtime/security test**: NOT performed.
- For a proper code audit: inspect dependency pinning, auth endpoints, privilege matrix, secrets scan, tenancy queries, subscriptions, offline license verifier, backup restore, CI workflows; run on exact source and build. That is a subsequent product-by-product work order.
